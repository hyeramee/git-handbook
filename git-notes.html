팀 협업 가이드

팀의 변경사항은 PR과 리뷰를 통해 공유합니다.

1. 작업 공유

  • 시작할 작업을 팀에 공유합니다.
  • 관련 이슈와 요구사항을 확인합니다.
  • 다른 작업과 겹치는 파일을 확인합니다.
  • 작업의 완료 기준을 정합니다.

2. 브랜치 관리

  • main에서 작업 브랜치를 만듭니다.
  • 팀의 브랜치 이름 규칙을 따릅니다.
  • 하나의 브랜치에는 관련 작업을 담습니다.
  • main의 변경사항을 주기적으로 확인합니다.

3. 커밋 관리

  • 변경사항을 의미 있는 단위로 나눕니다.
  • 커밋 전에 diff를 확인합니다.
  • 임시 파일이 포함되지 않았는지 확인합니다.
  • 커밋 메시지에 변경 목적을 적습니다.

4. 코드 리뷰

  • PR에 작업 배경을 설명합니다.
  • 검토가 필요한 부분을 표시합니다.
  • 리뷰 의견의 이유를 확인합니다.
  • 수정한 내용을 리뷰어에게 공유합니다.

5. 병합 확인

  • 필수 확인 항목을 점검합니다.
  • 충돌이 있으면 작성 의도를 함께 확인합니다.
  • 승인된 PR을 main에 병합합니다.
  • 병합 결과를 팀에 공유합니다.

병합 후에는 최신 main을 기준으로 다음 작업을 시작합니다.

작업 전후에는 git status로 현재 상태를 확인합니다.
